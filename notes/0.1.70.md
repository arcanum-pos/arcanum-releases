## What's new
- **Compose mode, for nerdctl (and anyone who'd rather not hand over the engine socket).** Next to the existing Docker / Podman setup — where the installer gets the engine's socket and updates everything with one click — there's now a second way: the installer gets only the folder its compose.yaml is in. On Installeren it writes the full compose.yaml there (every container, the installer itself included) and asks you to run `nerdctl compose up -d` (or `docker compose` / `podman compose`); once you have, it checks that everything runs the new version and settings. Updates and settings changes (mail, SMS, login) work the same way: the installer writes, you run the command. It works with any engine, Rancher Desktop on containerd included. The install page offers it as soon as it's switched on there.
- **Try an installation on one machine over http.** A self-hosted installation's address may now be `http://localhost:8000` (or `http://127.0.0.1:8000`) — handy to spin one up quickly without a domain or certificate. Sign-in works; the browser treats localhost as secure. Anything other than localhost still needs https (and payment providers' callbacks and other devices need a real https address anyway).

## For self-hosted installations
- **Smaller, leaner images.** Every container now runs on a distroless Node 24 image: no shell and no package manager inside, so far less to patch. They run as the same user as before, so existing data volumes keep working. To look inside a running one, use `kubectl debug` (there's no `sh` any more).
- **Safer database copy before an update.** The backend's copy of its database before a new version is now made once — a restarted or recreated pod no longer overwrites it with the already-updated database — and a rollback puts it back exactly once.
- **A clearer message without a container engine.** With the Docker / Podman setup, an installer that finds no engine at its socket (nerdctl has none) now says so and what to do, instead of `connect ECONNREFUSED`.
- The build now runs entirely on Node 24 (no more Node 20 deprecation warnings).

## Updating
- Update as usual: the installer updates itself first, then the rest. No database changes.
