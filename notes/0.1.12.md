## What's new

### Your own Arcanum from start.kaboutersoft.be — no Deploy button, no GitHub
Getting your own installation no longer starts with a Deploy to Cloudflare
button, a GitHub account and an installer password:

1. On **start.kaboutersoft.be**, sign in and choose **Eigen installatie**.
   That account becomes the administrator of your installation.
2. Create a free Cloudflare account if you don't have one, click **Maak een
   token** (the right permissions are filled in) and paste the token back.
3. The installer is put on **your** Cloudflare account, with everything it
   needs; the token is only used for that and never kept on
   start.kaboutersoft.be.
4. Open your installer with the link you get: it signs you in, shows a
   **recovery code** once (keep it — it's the way in if signing in ever
   fails), and has one button: **Installeren**. Custom domain, your own
   login provider and the other settings are under **Geavanceerd**.
5. When it's done, **Open je Arcanum** takes you to your console, where a
   welcome screen asks for your organisation's name — or imports one from
   an export file, for instance the demo you took along.

From then on you sign in to the installer with the same account as in
Arcanum (or the recovery code). Installers set up the old way keep their
password and work as before.

### The installer updates itself
The installer is now part of every release. When you update, it first
replaces itself with the release's installer, then updates Arcanum — so
the installer that knows the new version is the one installing it. If
that self-update fails, nothing of Arcanum is touched; the page explains
how to roll back in the Cloudflare dashboard.

### A custom domain registers itself at the login provider
Setting a custom domain under Geavanceerd now also adds its sign-in
address to the installation's login client at login.kaboutersoft.be — no
manual step. The workers.dev address keeps working.

### One organisation per own installation
An own installation now holds exactly one organisation: its first, created
from the welcome screen or imported. "Nieuwe organisatie" and import are
only offered while there is none. (The demo platform, where demo
organisations are created from start.kaboutersoft.be, doesn't offer them at
all.) A demo organisation shows when it disappears, with **Neem je demo
mee** (export it) and **Eigen installatie**.

## Updating
Both points below apply when updating from **0.1.10 or earlier** (0.1.11
already contained them).
- **An installation that already has an organisation can't add a second
  one after this update.** If you run more than one organisation on one
  installation today, keep them — nothing is removed — but new ones can't
  be created there anymore.
- The update adds one database column (migration `0022_org_is_locked`,
  applied by the installer). No data changes.
